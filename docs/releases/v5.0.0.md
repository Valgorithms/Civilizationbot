## Compatibility contract

All normal GameServer host, kill, restart and map-swap commands must use the configured engine. OpenDream never falls back to DreamDaemon. Server IPC remains compatible with native BYOND: OOC/admin have two fields, direct messages three, bans four, and unbans two. Every record ends in LF; embedded record delimiters/newlines are rejected.

OpenDream dispatch precedes the Windows/portable native supervisor gate. Native
BYOND controls retain the bound supervisor completion protocol on those hosts;
unsupported native map control remains unavailable. The restart slash reply
distinguishes native supervisor readiness, OpenDream process completion and
legacy scheduling. `tests/local/opendream.php` covers the normal engine routes;
`tests/local/restart-command.php` captures the production listener and checks
private acknowledgement, delayed results, rejection and unavailable adapters.

File relays read at most 32 records/64KB per tick without deleting producer logs. Private durable checkpoints advance only after successful delivery, and a cross-process lock remains held during asynchronous delivery. Rotation/truncate-regrow uses file identity and a 64-byte tail binding. Records exceeding 64KB are audited without their contents and drained in bounded batches. Delivery is at least once: a crash after Discord accepts a message but before checkpoint publication may replay it. Host power-loss durability and indistinguishable identical-tail file replacement are not established. Raw logs provide display text only; authenticated structured webhooks supply moderation identity.

An empty verified-role result clears old membership files. Replacement failures reject the operation. Multi-file updates are not a transaction, and the game's polling consumer does not participate in bot file locks; queued IPC is not proof of application.

Membership updates retain the existing file object, owner, mode and Windows ACL
instead of publishing a mode-0600 temporary file over a potentially shared role
file. Writers open without truncation, acquire an exclusive lock, write all
bytes, truncate the old tail and flush before fulfillment. The lock coordinates
participating writers only. Readers can observe an in-progress update, and a
failure or crash after writing can leave partial contents; rejection does not
promise rollback. Neither single-file crash atomicity nor host power-loss
durability is claimed. New files retain ordinary parent/umask creation rules;
installation-specific game-reader access must be checked before deployment.

## OpenDream full-bot configuration

Set `engine` to `opendream`, `ip` to `127.0.0.1`, `basedir` to the controller runtime directory, `port` to the gameplay port, and a distinct integer `topic_port`. Add `control` with trusted absolute `python`, `controller`, `profile`, an existing `temporary_directory`, and boolean `enabled`. The profile must match this runtime and both ports. Missing or changed profiles fail closed. Map IDs must belong to its explicit allowlist.

The minimal `local-bot.php` entry point remains a separate isolated service, not the full command router. Do not enable official guild integration or reuse production credentials for testing.

## Migration contracts

- The branch now tracks the application `composer.lock`; `composer install`
  reproduces that reviewed dependency set. Preserve intentional local path
  repositories and review the manifest/lock delta in an isolated checkout before
  changing deployment dependencies. The directory-only bundle has its own minimal
  lock and does not replace the live application's vendor tree.
- Existing servers default to `engine: byond`. Full-bot OpenDream options use
  the `control` object described above; the separate `local-bot.php` profile uses
  `controls` and `config/local-opendream.example.json`. These shapes are not
  interchangeable. The controller's runtime/ports/maps must bind exactly, and
  disabled or missing adapters never fall back to native execution. Native
  Windows/portable controls retain their explicit supervisor configuration.
- `GameServer::Host()`, `Kill()` and `Restart()` return promises. Await their
  result and retain the engine-specific meaning: a native supervisor receipt,
  OpenDream process completion or legacy scheduling. `MapSwap()` is also async;
  native Windows/portable map control remains unavailable. Process completion
  alone does not establish OpenDream initialization or player readiness.
- `GameServer::unban()`, the Civ13 unban aggregate, and admin/whitelist/faction
  replacement methods return promises. Callers must await fulfillment before
  acknowledging completion and handle rejection. Empty role membership revokes
  the previous file. A rejected aggregate may follow successful writes to other
  destinations; no cross-server transaction is promised.
  Existing list-file access metadata is retained through an in-place update;
  native readers do not honor the bot lock and may observe partial contents.
  Check the intended game's read access and recovery procedure before cutover.
  `/updateadmins` returns 200 only for an already observed fulfilled operation,
  503 for an already observed rejection or synchronous construction failure, and
  202 while pending. Clients must treat 202 as queued rather than "lists
  updated"; the synchronous HTTP route cannot amend that response after a later
  asynchronous failure. Retain the bot's rejection logs. The message command and
  staff panel await the aggregate before reporting its terminal result.
- Legacy file chat now keeps producer logs and stores durable cursors in the
  private `relay-checkpoints` directory under `filecache_path`. Configure a
  writable private cache path, retain checkpoints across restarts and prevent
  concurrent writers. Without a previous checkpoint the reader starts at byte
  zero, so existing backlog can replay. Do not delete/truncate producer logs or
  remove checkpoints as an automatic migration. A crash after delivery but
  before checkpoint publication can duplicate a message. Oversized records are
  audited without their text and drained in bounded batches. Raw log text no
  longer supplies moderation identity.
- Every `/webhook/` route requires the configured nonempty shared key even for
  previously trusted/local addresses. Structured native actor fields must match
  the documented payloads; display names do not grant account authority. Review
  the existing game's configured sender contract without printing or replacing
  credentials. HTTP 202 means queued; preserve downstream rejection diagnostics.
- The opt-in directory remains disabled by default. Its status-only inventory
  never creates a GameServer or lifecycle control. Keep `launcher_directory` and
  `launcher_directory_status_targets` empty until the separate inventory and
  endpoint deployment gates in `../launcher-directory.md` are met.
