# CivilizationBot v5.0.0 release preparation

Status: in development. Do not tag or deploy until the acceptance checklist is complete.

## Compatibility contract

All normal GameServer host, kill, restart and map-swap commands must use the configured engine. OpenDream never falls back to DreamDaemon. Server IPC remains compatible with native BYOND: OOC/admin have two fields, direct messages three, bans four, and unbans two. Every record ends in LF; embedded record delimiters/newlines are rejected.

File relays read at most 32 records/64KB per tick without deleting producer logs. Private durable checkpoints advance only after successful delivery, and a cross-process lock remains held during asynchronous delivery. Rotation/truncate-regrow uses file identity and a 64-byte tail binding. Records exceeding 64KB are audited without their contents and drained in bounded batches. Delivery is at least once: a crash after Discord accepts a message but before checkpoint publication may replay it. Host power-loss durability and indistinguishable identical-tail file replacement are not established. Raw logs provide display text only; authenticated structured webhooks supply moderation identity.

An empty verified-role result clears old membership files. Replacement failures reject the operation. Multi-file updates are not a transaction, and the game's polling consumer does not participate in bot file locks; queued IPC is not proof of application.

## OpenDream full-bot configuration

Set `engine` to `opendream`, `ip` to `127.0.0.1`, `basedir` to the controller runtime directory, `port` to the gameplay port, and a distinct integer `topic_port`. Add `control` with trusted absolute `python`, `controller`, `profile`, an existing `temporary_directory`, and boolean `enabled`. The profile must match this runtime and both ports. Missing or changed profiles fail closed. Map IDs must belong to its explicit allowlist.

The minimal `local-bot.php` entry point remains a separate isolated service, not the full command router. Do not enable official guild integration or reuse production credentials for testing.

## Required acceptance before release

- [ ] Engine-aware normal command and slash routes: success, rejection, concurrent operations and unavailable controllers.
- [ ] Native lifecycle: ordered update/build/start, owned stop/restart, safe map IDs, Windows/WSL/Debian paths.
- [ ] OpenDream real isolated server: process control, Topic status and all five IPC consumers.
- [ ] File relay: durable checkpoints, log rotation, long lines, moderation and failed Discord transport.
- [ ] Role lists: admins, whitelist, factions, empty revocation and denied writes.
- [ ] Webhook routes: OOC/asay/IC, login/logout/rounds, attack/runtime/log delivery and authentication.
- [ ] Status/player counts and correct engine-specific connection links.
- [ ] Verification, bans/unbans, panic bunker and award/ranking features using injected effects.
- [ ] Final dependency installation, PHP supported-version CI, version marker, migration/release notes and exact-head review.
- [ ] Discoverable versioned repository skills, validated frontmatter and source-backed AGENTS/catalog.
- [ ] Installed-compatible phpDocumentor build and GitHub Pages publication: source SHA, useful API links, public assets/search, no secrets/vendor/runtime data.
- [ ] Bounded read-only stdio MCP source/read/symbol/docs tools: cancellation and strict path/output limits, actual temporary-state Windows/Linux protocol tests and installation examples.

## Verification so far

The public phpDocumentor 3.10.0 reference is at https://valgorithms.github.io/Civilizationbot/v5/. Publication from `7833706bbe4265bfd92167db4031bcc24763ab4c` passed generated link/search/provenance checks and public HTTP readback. Actual browser search found `OpenDreamControl::request()` and navigated to its populated signature/parameter anchor. Later changes require a fresh publication receipt before release.

`tests/local/relay.php` exercises production durable restart/partial/retry, cross-process lock exclusion, truncate-regrow, audited oversized draining, 9KB records and malformed checkpoint rejection. `tests/local/message-delivery.php` exercises actual Civ13 short/embed/attachment sending with injected channel results, including rejected transport propagation. These send no Discord messages. Installed DiscordPHP `dev-master 212bed1` has a separate `MessageBuilder::getAllowedMentions(): ?array` mismatch returning its AllowedMentions object; serialization remains correct. No dependency source was edited.

Structured OOC requires a nonempty configured `http_key` and constant-time matching scalar request key even from trusted/local IPs. The native webhook supplies client identity separately from display text; the bot validates and canonicalizes that bounded identity before moderation. Missing/malformed identity or message rejects before routing. `tests/local/ooc-webhook.php` exercises the actual handler with injected Discord/game relay results. Other webhook routes and asay caller identity remain audit gates. OOC HTTP 202 means queued, not delivered; deferred and rejected downstream delivery is not game or Discord acceptance.

Native `asaymessage` currently receives `key_name` display strings. Its authenticated route preserves message text and relays with a null actor and moderation disabled; it does not use that string for account sanctions or verifier attribution. Existing staff-presence notifications remain. A future canonical actor field requires a coordinated game contract and native caller tests before enabling account moderation there.

`php tests/local/server-compatibility.php <autoload>` exercises production outbound GameServer OOC/admin/DM methods plus five-channel framing, invalid field rejection, empty list replacement, append-log partial lines, delivery failure retry, truncation, bounded batches and overlapping calls. Existing `tests/local/opendream.php` and `tests/local/controls.php` pass locally. These isolated checks do not establish Discord delivery or whole-game acceptance.
